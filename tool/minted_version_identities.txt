# minted_version_identities.txt — which bytes each versionCode actually names.
#
# A versionCode's whole job is to identify ONE artifact. Nothing in this repo
# checked that it did, so nothing noticed when it stopped being true. This file is
# the record; tool/assert_version_identity.sh is the check that reads it, and
# tool/preflight_play_upload.sh gate 4 refuses an upload that contradicts it.
#
# FORMAT, tab-separated:
#   versionCode <TAB> signer-cert-sha256 <TAB> artifact-sha256 <TAB> status <TAB> note
#
# KEYED ON (versionCode, SIGNER). Same package + same certificate + same code means
# two files are mutually substitutable on a device, and no record can tell them
# apart by number. A debug-signed build at the same code cannot install over a
# release-signed one, so it is not the same failure and is not recorded here.
# Only RELEASE-signed identities (CN=SNGNav Upload) belong in this file.
#
# STATUS
#   minted     this code names these bytes, and no others we have found.
#   ambiguous  this code names MORE THAN ONE set of bytes. It can never be
#              uploaded: whichever one Play took, no record could say which one a
#              phone then held. Marking it is a human acknowledgement, not a
#              repair -- bytes that exist cannot be un-made.
#
# APPEND with:  tool/assert_version_identity.sh --record <file.apk>
# and COMMIT it. An unrecorded artifact is one nothing can compare against -- the
# same weakness that left tool/play_uploaded_version_codes.txt holding zero
# integers while nine codes had been minted.
#
