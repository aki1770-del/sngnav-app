## 2. データ種別ごとの回答

### 2-1. 位置情報 — Precise location（正確な位置情報）

| 項目 | 回答 |
|---|---|
| Collected（端末外に出るか） | **はい** |
| Shared（第三者に渡るか） | **はい**（AAE 推奨 — §3 参照） |
| Processed ephemerally（一時処理のみか） | **はい** — 座標はメモリ上のみ。端末にも保存しない (`main.dart:753-770` の経路、保存先なし) |
| Required / Optional | **Optional** — 同意しなければ送信は発生しない (`services/route_consent.dart`; 同意ゲートは deny-by-default) |
| 目的 | **App functionality**（アプリの機能） |

**端末外に出る 3 経路（これがすべて）:**

1. **警報・注意報の取得** — 同意した場合のみ、走行約 1 km ごとに現在座標を、その地域を管轄する公的気象機関のみへ送信（日本＝気象庁、米国＝NWS）。`main.dart:753-770` / `services/advisory_service.dart:12-17` / `services/provider_coverage.dart`
2. **経路検索** — ユーザーが**地図をタップして指定した**出発地・目的地の座標を OSRM 公開デモサーバー (`router.project-osrm.org`) へ。**GPS 現在地は経路検索へ自動送信されない。** `main.dart:868-885, 921-926, 956`
3. **地図タイルの補完** — 同梱オフライン地図の範囲外を表示したときのみ、タイル座標を `tile.openstreetmap.org` へ（→ 2-2 の Approximate 扱い）。`akita_map.dart:90` / `services/offline_basemap.dart:53-56`

**送信されないもの:** 気象庁アメダス観測値の取得は**固定の観測所 ID**（秋田周辺 5 地点）に対する要求で、**ユーザーの座標を含まない**。`jma_fetch.dart:24,48,134-154` / `main.dart:79-84`

### 2-3. アプリのアクティビティ / 診断 — Crash logs, Diagnostics

| 項目 | 回答 |
|---|---|
| Collected | **いいえ** |

理由（Play の「ユーザー起点の転送」例外に該当）: エラーログは端末内ファイルにのみ追記され（上限 200 KB、古い順に破棄）、**自動送信は一切ない**。端末外に出るのは、ユーザーが「ログを共有」を押して OS の共有シートで自分の選んだ相手に送ったときだけ。`services/error_log.dart:9-15,32,54,83,96` / `services/log_share.dart:96,101`

同じ扱い: **運転日記**（Ring-2）— 端末内ファイルのみ、共有は「日記を共有」タップ時の OS 共有シートのみ。**座標・経路・目的地は一切記録しない**（記録されるのは彼女が自分で打った文だけ）。`services/drive_diary.dart:14-25,135,264,307`

### 2-4. その他すべての種別 — 収集なし

**Personal info / Financial / Health / Messages / Photos & videos / Audio / Files & docs / Calendar / Contacts / Web browsing / Device or other IDs → すべて「いいえ」。**

根拠: アカウント機能なし・ログインなし・個人情報入力欄なし・**広告 SDK / 解析 SDK ゼロ**・独自サーバーなし。要求している権限は INTERNET / ACCESS_FINE_LOCATION / ACCESS_COARSE_LOCATION / WAKE_LOCK / VIBRATE の 5 つのみで、ストレージ・カメラ・連絡先・**バックグラウンド位置情報**は要求していない（配布マニフェスト `packaged_manifests/release/…/AndroidManifest.xml:15,21,22,27,45`（⚑ 行番号は 2026-08-24 に実ビルド成果物で再測定。旧記載の `:53` は現在 `<queries>` を指しており、主張は真・**引用先が壊れていた**。なお同マニフェストには 6 本目の `uses-permission` として `…DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`（`:75`、自己宣言・`protectionLevel="signature"`）が存在するが、AndroidX が自動生成する署名レベルの内部権限であり、ユーザーに提示されず Data safety の対象外。「5 つ」はユーザー向け `android.permission.*` の数） で確認）。

## 3. 判断が要る 1 点 — Chair が決めること

**論点:** 座標が気象庁 / NWS / OSRM / OSM へ渡ることを、Play の言う **"Shared"（第三者への転送）** と申告するか。

- **狭く読む余地:** 経路検索はユーザーが目的地をタップした結果であり、「ユーザー起点の転送」例外に当たると主張できる。
- **AAE の推奨: 3 経路とも "Shared" として申告する（広い方）。**
  - 理由 1: 警報取得は走行中 1 km ごとの**継続的**送信で、「1 回のユーザー操作」とは形が違う。
  - 理由 2: **過少申告はポリシー違反（公開停止のリスク）だが、過大申告は違反にならない。** 10 月 31 日という戻ってこない日程の前で、非対称なリスクの安全側を取る。
  - 理由 3: 我々のプライバシーポリシーは既にこの 3 経路を明記しており、申告と一致する。
- **これは法的判断であり AAE の権限ではない。** Chair が別の読みを採るなら、その読みでプライバシーポリシー側も揃える必要がある（両者の食い違い自体が指摘対象になる）。
